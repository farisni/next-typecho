# 博客长期建设清单

本文用于记录 Next Typecho 作为个人博客后续值得完善的事项，按实际收益和风险排序，不以继续微调视觉为主要目标。

## 一、当前优先级

推荐实施顺序：

```text
SEO 基础
  -> 评论防垃圾
  -> 数据库、图片和部署备份
  -> 图片存储治理
  -> 访问统计完善
  -> 阅读体验增强
  -> 安全策略加固
```

## 二、SEO 基础

### 目标

让搜索引擎和社交平台正确理解博客、文章和站点作者信息。

### 待办事项

- 为首页、分类页、标签页和文章页生成准确的 `title` 和 `description`。
- 为文章页增加 canonical 地址，避免不同参数产生重复页面。
- 增加 `sitemap.xml`。
- 增加 RSS 或 Atom Feed。
- 检查 `robots.txt`，禁止后台、登录页、安装页和内部 API 被索引。
- 增加 Open Graph 和 Twitter Card 元信息。
- 为文章增加 JSON-LD `Article` 结构化数据。
- 确认文章作者、发布时间、更新时间和封面图都能被结构化数据读取。

### 验收标准

- 文章分享至社交平台时能显示标题、摘要、封面和站点名称。
- 搜索引擎抓取时每篇文章只有一个主地址。
- `sitemap.xml` 只包含公开、已发布内容。

## 三、评论防垃圾和通知

### 目标

保证评论功能可用，同时避免机器人灌水和通知骚扰。

### 待办事项

- 对评论提交接口增加 IP、会话或设备维度的频率限制。
- 对短时间重复内容进行拦截。
- 增加敏感词和垃圾链接检测。
- 对包含多个外链的评论进入待审核状态。
- 必要时接入轻量人机校验，不要默认增加访客操作成本。
- 增加博主新评论通知，可配置开关。
- 后台支持按状态筛选、批量审核和批量删除。
- 对评论接口增加 CSRF 防护和请求体大小限制。

### 验收标准

- 正常访客可以连续完成合理评论，不被误伤。
- 同一来源短时间大量提交会被限流。
- 待审核、已通过、垃圾评论状态清晰可区分。
- 评论失败不会影响文章页面访问。

## 四、数据库、图片和部署备份

### 目标

确保文章、评论、设置和上传图片在服务器故障或误操作后可以恢复。

### 待办事项

- 定期备份 SQLite 数据库。
- 备份 `uploads` 图片目录。
- 备份生产环境配置和部署脚本，但不要把密码、Cookie 密钥和生产 `.env` 提交到 Git。
- 保留多份带日期的备份，避免最新备份本身损坏时无法恢复。
- 定期执行一次真实恢复演练。
- 部署前保留上一版应用和 Nginx 配置。
- 部署失败自动恢复上一版并重载 Nginx。

### 验收标准

- 可以从一份备份恢复文章、评论、用户和站点设置。
- 可以从上一版构建产物快速回滚。
- 备份任务失败时有明确日志或通知。

## 五、图片存储治理

### 目标

控制图片带宽、磁盘和 Sharp 处理资源，避免上传功能成为服务器压力来源。

### 待办事项

- 上传前校验文件类型、扩展名、文件大小和图片尺寸。
- 只允许明确支持的图片 MIME 类型。
- 使用 Sharp 生成 WebP 或 AVIF，同时保留合理的 JPEG/PNG 兼容策略。
- 限制单张图片原始上传大小和总像素数。
- 使用随机文件名，禁止用户输入直接成为文件路径。
- 确保 uploads 目录不能执行脚本文件。
- 文章删除或修改后，扫描无引用图片，提供安全清理工具。
- 继续由 Nginx 直接提供上传图片，避免静态图片经过 Next.js。

### 验收标准

- 超大图片在进入 Sharp 前就会被拒绝。
- 上传的文件不能通过服务器执行。
- 常见设备图片都能正常压缩和显示。
- 图片访问不会明显增加 Node.js 进程负载。

## 六、访问统计完善

### 当前口径

- PV：页面每成功上报一次，增加一次页面浏览量。
- UV：同一访客在同一天内只计一次，浏览多个页面和刷新不会重复计入当天 UV。
- 访客标识保存在浏览器 `localStorage` 中，服务端只保存哈希值。
- 当前“今日 UV”是当天全站去重结果。
- 当前“近 120 天 UV”是每日 UV 累计，不是跨 120 天完全去重后的访客数。

### 待办事项

- 过滤明显的爬虫、监控探针和后台请求。
- 增加来源页面或来源域名统计。
- 增加热门文章、设备类型和浏览器统计。
- 对统计接口增加基本限流和异常请求过滤。
- 增加数据保留周期和清理策略。
- 在面板中明确显示统计时间范围和 PV/UV 含义。
- 统计失败时不能阻塞页面访问。

### 验收标准

- 同一访客当天浏览多个页面，UV 仍只增加一次。
- 页面刷新不会在短时间内重复产生异常 PV。
- 统计接口异常时首页和文章页仍然正常。
- 面板数字可以追溯到明确的时间范围和统计口径。

## 七、阅读体验

### 待办事项

- 文章图片点击后支持大图查看和关闭。
- 代码块显示语言标识，并提供不占独立行的复制按钮。
- 复制成功后给出轻量反馈，不改变代码块高度。
- 文章目录随滚动高亮当前标题。
- 长文章增加返回顶部入口。
- 完善文章页、搜索页、评论区的加载状态。
- 增加 404、500 和数据加载失败页面。
- 继续检查移动端评论框、代码块和侧边栏的溢出问题。
- 确保键盘可以操作搜索、评论、目录和弹窗。

### 验收标准

- 手机屏幕不出现横向滚动。
- 代码、图片和评论在窄屏下仍可阅读。
- 交互控件具备可见焦点状态和可读的辅助标签。

## 八、安全策略

### 待办事项

- 增加 `Content-Security-Policy`，先以报告模式观察，再逐步收紧。
- 增加 `X-Content-Type-Options: nosniff`。
- 增加合适的 `Referrer-Policy`。
- 登录、评论、搜索和上传接口分别设置请求体与频率限制。
- 确认上传目录不允许执行 PHP、JavaScript 或其他脚本。
- 生产环境密钥只从环境变量读取。
- 定期更新 Next.js、Node.js、Sharp 和依赖包，并查看安全公告。
- 不在公开页面暴露过多服务器信息。
- 博主邮箱可考虑使用联系按钮或邮箱混淆，减少爬虫收集。

### 验收标准

- 安全响应头在 HTTPS 页面生效。
- 上传文件无法被当作脚本执行。
- 登录和评论接口对高频请求有保护。
- 依赖升级后不会引入明显的构建或 hydration 错误。

## 九、生产运维

当前 Nginx 参数和原因见：

[Nginx 生产配置说明](./nginx-production-config.md)

后续部署应继续遵循：

- 先构建，再部署。
- Nginx 修改后先执行 `nginx -t`。
- 校验通过后再执行平滑 reload。
- 保留上一版应用和 Nginx 配置。
- 部署失败时自动回滚。
- 记录部署版本、时间和数据库迁移结果。
- 关注 CPU、内存、磁盘、带宽、Node.js 错误日志和 SQLite 锁等待。

## 十、实施原则

- 先处理数据安全、评论安全和部署可恢复性，再继续细化视觉。
- 每次只改一个主要方向，便于定位回归问题。
- 业务缓存和 Nginx 缓存保持清晰边界，不对登录态和个性化页面启用全站动态缓存。
- 统计、通知和监控失败时不能阻塞访客正常阅读。
- 公开邮箱、访客标识和评论数据都要以最小必要原则处理。
- 每项改动都记录原因、影响范围和回滚方法。
